01 · Objective

Build the pipeline before scaling the drawings

The implementation will produce a cumulative electrical representation of the one-box capstone for fourteen project states: Week 0 infrastructure and Weeks 1–13. Each state must show the physical project honestly, emphasize that week’s active experiment, and identify additions, removals, replacements, and inactive retained circuitry.

Primary release contract

For every released week, the SVG schematic and SPICE netlist must be derived from—or mechanically proven equivalent to—the same canonical circuit graph.

In scope

  • A reviewed week-by-week electrical specification before circuit implementation.
  • A canonical representation for components, pins, nets, parameters, variants, and weekly state.
  • One cumulative main electrical sheet per week, plus pin-for-pin detail sheets where needed.
  • Recommended-values tables and implementation notes.
  • Ideal and realistic SPICE variants where the weekly circuit is expected to operate.
  • Automated equivalence, electrical, provenance, and regression checks.
  • Approved SVG integration into capstone.html.

Not in the first implementation

  • Physical front-panel patch-cord paths and routing diagrams. Electrical nets and ordinary schematic wires remain in scope.
  • A low-voltage redesign.
  • Full parallel modern schematics unless a substitute materially changes topology.
  • Physical board placement, harness routing, and front-panel mechanical design.
Current boundary

Creating this plan does not cross Gate 0. No circuit implementation begins until the weekly specification is written, reviewed, and explicitly approved.

02 · Architecture

One model, controlled projections

The implementation must separate electrical truth from presentation without allowing them to drift.

LAYER 01
Canonical circuit modelStable component IDs, pin definitions, named nets, values or symbols, model bindings, hierarchy, state, and provenance.
AuthorityThe only editable electrical source of truth.
LAYER 02
Weekly compositionWeek N imports the prior physical state and applies an explicit delta: add, change, remove, replace, activate, or retain-inactive.
AuthorityCumulative state and presentation semantics.
LAYER 03
Schematic projectionElectrical symbols, pin-connected wires, named modules, visual layout hints, current-week highlighting, and detail-sheet boundaries.
OutputPublication SVG plus machine-readable connectivity receipt.
LAYER 04
Simulation projectionIdeal and realistic device bindings, supplies, stimuli, analyses, expected measurements, and known non-operational states.
OutputSPICE netlists, plots or scalar results, and test receipt.
LAYER 05
Publication projectionSVG embedding, recommended-values tables, source citations, historical notes, modern notes, and status explanations.
OutputUpdated capstone presentation after release approval.
Tool choice remains gated

The plan does not preselect lcapy, KiCad, SKiDL, or another renderer. The selected stack must demonstrate deterministic connectivity, analog layout control, SVG output, SPICE compatibility, Windows reproducibility, and programmatic equivalence checking on the Week 9 proof.

01

Weekly electrical specification

Resolve the circuit before selecting the drawing machinery.

Gate 0 · user approval

Tasks

  • Read the relevant Roberge pages and figures for every week.
  • Describe the end-of-week physical state, active experiment, inherited circuitry, and exact delta.
  • List components, pins, named nets, hierarchy, module boundaries, symbolic parameters, and recommended values.
  • Identify practical additions not explicit in Roberge and explain why each is necessary.
  • Record power assumptions, test points, loading, matching, tolerances, ratings, and expected measurements.
  • Mark incomplete/nonfunctional weeks and define what can and cannot be simulated.
  • Carry D-01 through D-04 into the specification.
  • Specify separate Week 12 Butterworth and Van der Pol configurations and separate Week 13 compensation-campaign configurations.
  • Use LM301A as the primary historical stock op-amp and record 741-class alternatives explicitly.

Issue ledgerContradictions, missing values, ambiguous adaptations, and decisions requested from the user.
Exit criterionUser approves the specification and explicitly authorizes implementation.

05

Chronological weekly production

Generate cumulative states in dependency order, not as independent pictures.

Gate 3B · weekly batches

Tasks

  • Implement Weeks 1–4: computing core and first/second-order loops.
  • Implement Weeks 5–6: regulator plant and test oscillator.
  • Implement Weeks 7–10: honest discrete-channel evolution, including incomplete states and the already-proved Week 9.
  • Implement Weeks 11–13: three-mode integration, final problems, and compensation.
  • At every transition, verify prior state plus explicit delta and record all removals or replacements.
  • Apply the one-large-sheet preference, adding detail sheets only under the approved readability rule.

04 · Weekly map

Fourteen states to specify and release

Week 0 · infrastructure

Permanent electrical foundation

Dual ±15 V interface, ground architecture, local decoupling, protection, connector conventions, and hidden power-pin contract.

Week 1 · Chapter 1

Computing core

Installed inverter, weighted summer, and first integrator; complete cumulative chassis state with each active test configuration identified.

Week 2 · Chapter 2

First closed loop

Prior core plus the active first-order computer configuration; patch-cord depiction remains deferred but electrical connectivity cannot be ambiguous.

Week 3 · Chapter 3

Characterized existing machine

Week 2 state plus compensation configuration and measurement setup required for the experiment.

Week 4 · Chapter 4

Second integrator and loop

Cumulative core with the second integrator and active second-order loop, including stability measurement points.

Week 5 · Chapter 5

Physical regulator plant

Existing computer retained; regulator plant installed and emphasized as the active experiment, with inactive modules subdued.

Week 6 · Chapters 6/12

Test oscillator

Cumulative chassis plus Schmitt–integrator oscillator configured as the active source.

Week 7 · Chapter 7

Discrete input stage

INT1 IC physically removed; socket retained; incomplete differential input stage shown honestly and not anticipated as a finished amplifier.

Week 8 · Chapter 8

Completed discrete channel

Week 7 pair plus high-gain stage, current-source load, complementary output, and feedback element needed to restore the channel’s role.

Week 9 · Chapter 9

Illustrative amplifier and proof slice

Figure 9.1-era channel with compensation and measurement configuration; selected as the end-to-end pipeline proof.

Week 10 · Chapter 10

IC-practice improvement

Same discrete channel with current-repeater load and explicit comparison points against a stock integrated amplifier.

Week 11 · Chapters 11/12

Reset, operate, hold

Cumulative machine with switching modes around the integrators and retained precision-rectifier capability.

Week 12 · Chapter 12

Capstone problems

One cumulative physical state with separate complete configuration sheets and matched netlists for the Butterworth and Van der Pol experiments; the regulator analog twin is documented without conflating configurations.

Week 13 · Chapter 13

Compensated finished machine

Final cumulative state with separate configuration sheets and matched netlists for the fixed-transfer and amplifier-transfer compensation campaigns.

06 · Verification

Tests that correspond to the actual failure modes

V-01

Schema and identity

  • Unique stable component IDs
  • Valid pin names and model bindings
  • No undeclared nets
  • No illegal weekly state transition
  • All removals explicitly recorded
V-02

Connectivity equivalence

  • Normalized component-set equality
  • Pin-to-net equality
  • Hierarchy boundary equality
  • No SVG-only or SPICE-only elements
  • Intentional model substitutions declared
V-03

Electrical checks

  • DC operating point
  • Expected gain and polarity
  • AC response and stability where relevant
  • Transient response and saturation
  • Explicit expected failure for incomplete states
V-04

Cumulative progression

  • Week N equals Week N−1 plus declared delta
  • Retained inactive circuitry preserved
  • Removal/replacement annotations present
  • Coral highlight matches delta
  • Active experiment receives normal emphasis
V-05

Visual and publication

  • No overlap, clipping, or ambiguous crossing
  • Explicit junctions and readable labels
  • Main/detail interfaces match pin-for-pin
  • Desktop, narrow-screen, and print review
  • All local links and SVG references resolve
V-06

Source and engineering review

  • Roberge figure/section cited
  • Practical additions identified
  • Values and ratings reviewed
  • Historical and modern notes separated
  • Known deviations and uncertainty visible
Important exception

A temporarily incomplete Week 7 channel should not be forced to pass a functional simulation. Its acceptance criteria are faithful topology, expected non-operation, safe state assumptions, and correct cumulative representation.

10 · Governance

User decisions occur at five checkpoints

  1. Gate 0 — specification approval: approve fourteen weekly end states, source adaptations, recommended-value strategy, and unresolved issues.
  2. Gate 1 — architecture approval: approve the canonical model, renderer/simulator stack, fallback, and reproducibility policy.
  3. Gate 2 — Week 9 proof approval: approve the electrical fidelity, presentation language, values table, notes, and test receipts.
  4. Gate 3 — batch reviews: approve each chronological group before the next group is scaled.
  5. Gate 5 — final acceptance: accept the integrated capstone, known limitations, reproducibility evidence, and deferred-project handoff.

Questions should be raised at the earliest gate that can resolve them. A later polished drawing must not conceal an earlier unresolved circuit decision.

11 · Completion

Definition of done

  • Week 0 and Weeks 1–13 each have an approved cumulative state and explicit delta.
  • Every released schematic and SPICE netlist has matching components, pins, and nets.
  • Every main/detail sheet boundary matches pin-for-pin.
  • Every applicable ideal and realistic simulation passes documented expectations—or has an explicit, technically justified exception.
  • Every circuit cites its Roberge source and identifies practical additions.
  • Every weekly output includes recommended values, ratings or constraints, historical notes, and modern notes where relevant.
  • Week-to-week highlighting matches the actual cumulative delta.
  • Week 7 and other incomplete states are represented honestly.
  • The integrated capstone passes local-link, responsive, print, accessibility, and visual checks.
  • A clean documented regeneration reproduces the published outputs and receipts.
  • D-01 through D-04 remain visible with triggers and prerequisites.
  • The final receipt distinguishes verified evidence, implementation decisions, known limitations, and future work.
